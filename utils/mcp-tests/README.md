# MCP smoke-тесты

## Назначение

Тест проверяет опубликованную MCP-связку для каждой библиотеки после загрузки MCP-данных:

```text
manifest → MCP-сервер → tools/list → tools/call
```

Проверяется не только доступность `manifest.json`, но и то, что запущенный MCP-сервер действительно отдаёт именно разрешённые в манифесте tools и может выполнить каждый из них.

## Принцип работы

Для каждой библиотеки CI выполняет один и тот же сценарий:

1. Загружает versioned `manifest.json` из S3 через публичный URL.
2. Проверяет, что в манифесте есть непустой массив `tools` без дубликатов.
3. Запускает опубликованный MCP-сервер отдельным процессом через `npx`:

    ```bash
    npx -y @salutejs/sdds-mcp@latest \
      --lib plasma-web \
      --version 1.644.0
    ```

4. Подключается к процессу через MCP stdio-протокол.
5. Выполняет `initialize`.
6. Запрашивает `tools/list` и сравнивает результат с `manifest.tools`:
    - все разрешённые tools опубликованы сервером;
    - запрещённые tools не опубликованы;
    - лишние tools отсутствуют.
7. Вызывает каждый tool из `manifest.tools` с тестовыми аргументами.
8. Проверяет, что:
    - MCP-запрос не завершился протокольной ошибкой;
    - результат не содержит `isError: true`;
    - ответ содержит непустой текст;
    - текст является валидным JSON;
    - для основных tools соблюдается минимальная структура ответа.

Ошибки выполнения tools проверяются через `result.isError`, а не через поле JSON-RPC `error`. Поле `error` используется для ошибок самого MCP-протокола, например неизвестного метода.

## Аргументы tools

-   `list_components` вызывается без аргументов. Имя первого компонента используется как fixture для `get_component`.
-   `get_component` вызывается с именем первого компонента.
-   `search_icons` вызывается с запросом `arrow` и ограничением `5`.
-   Остальные текущие tools вызываются без аргументов.

Если tool отсутствует в `manifest.tools`, он не вызывается. Поэтому, например, `get_nextjs_guide` проверяется только для вертикалей, где он разрешён.

## Локальный запуск

```bash
npm run test \
  --prefix=./utils/mcp-tests \
  -- \
  --lib plasma-web \
  --version 1.644.0
```

Дополнительные параметры:

```text
--server-version <version>
--server-package <package>
--manifest-base-url <url>
```

## Запуск в CI

Job `test-mcp-data` запускается после успешных `upload-mcp-data` и `upload-icons-manifest`. Для каждой библиотеки создаётся отдельная matrix-задача. Если upload завершился с ошибкой, тесты не запускаются.

Сейчас тест проверяет MCP-сервер и ответы tools. Проверка всех `href` из индексов и полноты данных в `mcpData` может быть добавлена отдельным этапом.
